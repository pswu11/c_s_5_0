sort1 uses: Bubble Sort

How do you know?:

Both bubble sort and selection sort have upper bound of
O(n^2) complexity. However, if you look closely on the fomulars,
bubble sort's time complexity should be higher than selection
sort as the number of comparisons increases.

Based on the execution time we received, while sorting the 5000 numbers
doesn't show a huge difference between two algorithms, but the gap between
sort1 and sort3 became very obvious when sorting 50000 numbers.

sort2 uses: Merge Sort

How do you know?:

Merge sort is a way more efficient sorting algorithms than selection
sort and bubble sort that has a complexity of O(n log n), and its
upper bound and lower bound are the same. Therefore, it's obvious that
sort2 program is using merge sort algorithm. (See NOTES below)

sort3 uses: Selection Sort

How do you know?:

Selection sort's upper bound and lower bound complexity are both O(n^2).
That means the difference of execution time between the best case and
worst case should be neglectable.

We can see that for sort3, the execution time between random and reversed
dataset are quite small, especially when comparing to sort1.
